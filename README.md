# Mgame-GCenter 游戏中心金币任务

在 Windows 上通过 ADB 操作已授权的 Android 手机。手机解锁后打开美团游戏中心的「玩游戏」首页。程序按游戏卡上的金币标识选择任务。

| 区域 | 实测入口 | 等待时长 |
|---|---|---|
| 好游推荐 | 横向卡片，同一张卡同时显示「试玩60秒+10」和「去玩」 | 读取卡片秒数 |
| 小编精选 | 大卡的「去玩」，或带金币标识的小图标下方的游戏名 | 读取区域说明，本机为 80 秒 |
| 热门内容 | 双列卡片中，标题旁有「+」及奖励数的游戏 | 读取区域说明，本机为 120 秒 |

### 本机运行

在本目录打开 PowerShell。默认模式列出当前页面已加载的奖励卡，包括需要滚动才可点击的卡片。

```powershell
.\run.ps1
.\run.ps1 -Section recommend -Execute -Limit 1
.\run.ps1 -Execute
```

`-Section` 支持 `all`、`recommend`、`editor`、`hot`。`-Limit` 限制本次尝试的轮数，默认 0 表示执行所选区域。多台设备可用 `-Serial` 指定序列号。脚本优先使用项目的虚拟环境，也支持同级 FCash 项目已安装的 Python。

独立部署需要 Python 3.10 或更高版本、OpenCV、NumPy 及 Android Platform Tools。将 adb 加入 PATH 或放在 Windows 用户目录的标准 Android SDK 路径。可用以下命令准备独立环境。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 gcenter.py --execute
```

直接运行 Python 时，省略 `--execute` 可预览当前已加载的任务。使用 `--section hot --execute` 只跑热门内容，追加 `--serial` 可选定设备。

### 计时与结算

执行时先定位好游推荐所在的首屏，再扫描所选区域。小编精选会把新游戏放到旧卡片的同一位置，程序只选择该位置上最前面的卡片。热门内容即使显示「任务已完成」，仍逐张读取金币标识。时长依次取自卡片、区域说明、三个区域的默认值（60、80、120 秒）。日志的 `duration_source` 记录实际来源。

小游戏进入前台后，程序按要求时长加 1 至 2 秒计时。遇到已识别的插屏会查找「关闭」或「跳过」。如果插屏打开了外部应用，程序会在有限次数内切回已识别的原美团任务。回到原游戏后继续累计前台时间。游戏提前退回美团时，程序尝试回到游戏中心，按页面标识复查。

每轮最多读取三次页面。连续两次看到原游戏的标识消失，或看到小编精选在相同位置换上新卡，才记录 `confirmed`。卡片移出当前页面会记录为待复查。同一区域同名游戏每次执行最多尝试两轮。已有卡片仍带标识、准备重跑时，先重新进入游戏中心复查。热门内容连续两次滑动后可见卡片及位置均未变化时，如果还有未用完重试次数的卡片，会从首屏回扫一次。

完成复查后，程序复用最后一次读取的页面选下一款，省去重复的界面树读取。点击、滑动或页面切换后重新读取。默认模式累计游戏实际处于前台的时长。

### 桌面等待试跑

使用 `-Timing desktop` 或 Python 的 `--timing desktop` 选择桌面等待。脚本先确认小游戏已打开且与游戏中心处于同一个 Android 任务，再回到系统桌面。桌面等待采用页面规定时长加 1 秒。时间到后恢复原游戏任务，退出回游戏中心并按原有的两次金币标识核验。全量运行时，同一张卡若需要再次尝试，会改用前台计时。

```powershell
.\run.ps1 -Section hot -Execute -Timing desktop -Limit 1
# 单卡验证通过后可用同一模式测整区
.\run.ps1 -Section hot -Execute -Timing desktop
```

单卡试跑以 `desktop_timer_finished` 后出现 `confirmed` 和 `limit_reached` 为成功。若仍有金币标识，检查 `unconfirmed`。若桌面或游戏任务状态变化，检查 `round_interrupted` 和现场截图。记录从 `open` 到 `confirmed` 的耗时，与同一游戏的前台运行日志对比。

### 中断后继续与查看结果

游戏启动或返回出现已识别的异常时，程序尝试在当前执行中恢复，先核对原卡标识，再处理仍有标识的任务。恢复时根据美团任务栈识别游戏、插屏及应用内广告落地页。站内广告页用系统返回无效时，程序核对网页顶栏的「关闭」或「返回」后退出。网页中的身份核实由用户处理。已识别的游戏更新提示优先选「取消」，只有「确认」时按该提示重启，再核对同一任务栈中的游戏并返回。若程序中止，把手机停在游戏中心后重新运行同一命令即可。重新打开仍有标识的游戏会重新计时。

全程扫描结束时仍有待核对项，Python 会在同一进程内重新打开游戏中心，只复查相关区域。好游推荐和小编精选需要两次读到相同名单、可见卡片和零标识，才可清除已被替换的待核对卡。热门内容的旧卡分页后暂时不可见时，继续保留待核对状态，直到两次看到同名卡片没有标识。

执行时遇到「桌面入口提示」，程序会点「不需要」并重新读取游戏中心。预览模式会提示先关闭弹窗。若同一款游戏两轮结束后仍有金币标识，日志会记录 `gameplay_check_needed`，可在该游戏中正常游玩一局后返回复查。

每次执行的记录位于 `runs/*.jsonl`。单轮中断或执行停止时，程序尝试在同目录保存现场 PNG。查看最后一个日志的末尾可确认本次执行的范围和结果。

```powershell
$latest = Get-ChildItem .\runs\*.jsonl | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-Content -LiteralPath $latest.FullName -Encoding UTF8 -Tail 8
```

| 日志事件 | 含义 |
|---|---|
| `round_interrupted`、`round_recovered` | 单轮遇到启动或返回异常，以及恢复到游戏中心准备复查。 |
| `ad_closed` | 关闭插屏后的剩余前台计时为 `remaining`，此次处理耗时为 `handling_seconds`。 |
| `ad_web_toolbar_tapped`、`game_update_dismissed` | 记录实际使用的广告页顶栏或游戏更新控件。 |
| `desktop_timer`、`desktop_timer_finished` | 已确认进入桌面开始等待，以及等待结束并恢复原游戏任务。完成事件记录实际等待秒数。 |
| `desktop_timer_fallback` | 桌面等待条件未满足，原游戏在前台时转为前台计时。 |
| `round_timing` | 单轮打开游戏、游戏阶段、退出、核验和异常恢复的耗时。游戏阶段包含选定模式下的等待与恢复。 |
| `section_checked` | 区域扫描耗时、计划前台时长和计划桌面等待时长。`still_marked` 是当前页面仍有标识的游戏，`unresolved` 是待核对的游戏及原因。 |
| `pending_section_checked`、`pending_recheck_finished` | 只复查相关区域后的结果和复查总耗时。 |
| `run_completed` | 所选区域全部扫完、待复查项为空，手机已回到游戏中心首屏。`elapsed_seconds` 是本进程的运行耗时。 |
| `limit_reached` | 达到 `-Limit` 指定的尝试轮数。 |
| `stopped` | 执行中止，Python 退出码为 2。记录包含原因，以及中止时已知的区域、游戏和最近事件。 |
| `screenshot`、`screenshot_unavailable` | 现场 PNG 文件名或无法截图的原因。 |

可用 `python -m unittest -v` 在电脑上运行离线回归测试。
